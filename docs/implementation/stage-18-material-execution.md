# Stage18 源动作材料到身体执行

## 1 本次做什么

打通E3/E4材料输出到E2身体适配：源局部姿态 → 层级FK → 与原BVH相同单位的骨架采样 → 校准旋转映射 → 目标姿态。支持移动窗口产生的中间姿态，不把动作重新编码为欧拉角BVH。保留旧按时间调用API作为对照。

Example：`examples/stage-18-material-execution/user_code/main.mjs`。断点：米/源单位转换、父子FK、映射目标世界旋转与目标最终局部四元数。验收：原始整帧和材料整帧一致、中间过渡能改变目标、非法数据在修改目标前拒绝、旧测试无回归。先完成数值执行桥，再接实际研究UI；音乐仍独立。

### 已执行数值检查

`npm test`119/119通过；旧apply(time)与applyFrame在height/source/balance上保持等价，非法输入拒绝且目标姿态不变。原创31采样移动过渡驱动合成19骨目标，最大标定残差2.98e-8 rad，上臂变化0.477rad；不是只跑材料而未执行身体。

本地1901帧、27关节完整BVH经材料/FK回转，矩阵分量最大差1.99e-13，见`docs/evidence/material-skeleton-source-roundtrip.json`。量纲：平移为源单位，旋转为无量纲矩阵项，不能将这个混合矩阵差当米制身体误差。

研究页已构建和打包，签名检查通过。当前默认出段9秒、入段12.6秒、1.5–2秒过渡；过渡开始两侧髋部源世界位置相隔约1.480m（显式0.01米/源单位假设）。因此即使姿态/速度端点正确，未对齐片段仍可能造成明显场景横移。镜头跟随只改善观察，不能算已修复轨迹。下一轮须对齐根轨迹/朝向，记录变换来源，再结合接触检查。

### 原生VRM连续检查

隔离Electron窗口载入用户本地VRM与BVH，未加载正式main、不改用户设置。121帧/30fps覆盖0–4秒，每帧UI时间断言通过；另实际播放至4.000秒自动停止，无renderer和UI错误。过渡期可见抬腿回收、侧身再回正，证明确实执行移动窗口的不同姿态。
