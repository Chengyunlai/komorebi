# 烟花录像观感复核

日期：2026-11-03。用户反馈最新40秒录像“怪怪的，效果没之前好”。本轮交付为录制复核和问题分流；没有修改运行代码或将未确定原因写成已修复。

## 已确认事实

复核三份本机MP4：原公开演示（from-start-40s）、切歌修复前烟花版（hand-fireworks-opening-40s）、切歌修复后烟花版（track-reset-fireworks-40s）。按成片时间逐秒抽帧、关键位置100ms抽帧，并检查原始screencast帧时长。

最新40秒成片范围内，原始捕获有13段超过200ms的间隙，每段约266–284ms，间隙总时长约3.584秒（不是说每段全时长均为可见冻结）。位置为7.782、9.432、12.566、15.500、18.167、20.683、23.249、25.550、28.432、30.633、32.950、35.467、37.649秒。

15.5/15.6/15.7秒导出帧中人物姿态相同，15.8秒跳到明显不同的俯身伸腿动作。导出按时间戳补齐1200帧只能保证40秒和标称30fps，不能重建这些间隙里未捕获的动作；此前时长/抽帧验收漏掉了连续性问题。

完整44.72秒捕获平均27.24帧/秒；修复前烟花版44.66秒平均28.51帧/秒，同样有周期性约267ms间隙。按15fps分析整段人物区域，最新/修复前烟花版各有40/55个低变化帧（平均RGB差<0.3），原公开演示为0。像素差仅是定位工具，不是舞蹈质量分数。

目视判断：手部烟花部分出现在腰边或垂下的手旁；手离开后残留粒子独立扩散。当前手部评分总会从可用手中选优，没有要求形成明确伸展/抬手发力，因此空间定位正确不代表时机和动作表达合适。小粒子在深灰背景下偏碎、偏弱，是观感问题；不能仅凭“有粒子”验收炫感。

## 推断与未知

两个烟花版本都有类似间隙，当前证据不足以将本次退步单独归因于切歌修复。烟花渲染、动作选窗、音频分析与screencast捕获通道仍需同输入开关对照/性能采样来分离。不能从捕获间隙直接断言实际桌面渲染同样停止。

实际窗口在音频off、可见状态下的12秒诊断中rAF约721帧，未观测到>90ms间隙或longtask；这只说明空闲情况，不代表音乐+烟花+录制情况正常。

本轮没有完成精准拍点的听觉标注，未用整体运动量推断踩拍质量，也没有因测试253项通过而认定视觉交付通过。

## 结论与下一步

当前烟花演示观感未通过。优先用同一段已录音乐隔离烟花开关及录制开关，定位并消除反复停顿；保持切歌取消旧窗口的需求。之后收紧触发到有明确抬手/伸展动作的音乐重音，检查完整40秒后再重录交付。避免通过放大动作或增密烟花掩盖卡顿。
