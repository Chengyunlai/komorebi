# Stage46 播放连续性修复（低活动段/卡住问题）

## 本次做什么

用户反馈"一直卡住的动作"（角色长时间站立不动）。诊断：

- 播放器在推进（`danceSourceFrame` 持续增加）→ 不是卡死，而是**选段选到了库中的近静止片段**（舞蹈开头/预备/停顿），播放出来像站着不动。
- 根因：motion matching 的选段只按"能量匹配 + 姿态连续"，未排除低活动段。

## 修复

1. **选段活动度下限**：`chooseStart` 跳过活动度 < max(targetActivity×0.45, 6% 最大值) 的起点。
2. **播放中低活动提前切换**：当前段活动度过低且段已"成熟"（≥60% 段长）时立即重新选段。
3. 修复 `targetActivity` 作用域（在 step 中计算）。
4. 更新 freestyle-motion 测试（近静止段被排除后，不同能量都应落在活动段）。

## 结果、验证与结论

- 连续 12 帧截图：动作持续变化（摆臂、转体、蹲腿、倾斜），不再长时间静立。
- 222 测试通过。

## 资源和调整

- `src/motion/freestyle-motion.mjs`（活动度下限 + 提前切换）；`tests/freestyle-motion.test.cjs`。

## 进一步评估与下一步

- 观感：段长 2.4s、过渡 0.6s、活动度下限 45% 可再调。
- 若某些歌曲安静段确实需要"轻动作"，可让下限随能量自适应（已部分实现）。
