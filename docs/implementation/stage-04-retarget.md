# 完整舞蹈上半身重定向预览

目标：从真实BVH姿态提取头、躯干和手臂的几何特征，生成当前日和可播放的8通道 motion3；在同一时钟下并排比较原始骨架与人物。先验证动作表现上限，不将研究数据直接接入日常桌宠或音乐编排。

原始骨架 → 躯干参考坐标系与头部相对旋转、手臂抬起角度 → 校准/平滑/限幅 → 原生SDK播放。
明确丢弃肘、髋腿脚独立动作及根节点位移；允许整体增益和左右镜像校验；显示被压缩/限幅的比例。
研究BVH及生成动作仅本机内存/工作目录保留，不随app与源码分发。纯映射代码和合成测试可正常分发。

Example: examples/stage-04-retarget/user_code/main.mjs。断点：measureUpperBody、retargetPose、buildRetargetMotion、MotionStage原生SDK播放。
验证：坐标变换与左右协同、时间戳与限幅、缺少关节拒绝映射；真实63秒样本完整生成；原生UI并排播放及Core采样对照。当前工作树未提交。

## 实现与验证

- 原始1901帧、63.33秒成功生成8通道motion3；纯映射逻辑在 retarget.mjs，完整生成在独立Web Worker执行，界面不阻塞。
- 39项测试通过；覆盖左右臂独立、镜像交换、整体平移不伪造成躯干动作、原始帧时间、限幅限速、零增益、缺少关节与目标通道时拒绝生成。
- 身体转向改为周期投影，避免背向转身时正负180度翻转；俯仰和侧倾从上方向量提取；90ms平滑和每秒4单位限速。骨架相机按整段动作范围留出举手空间。
- 原生界面已运行“骨架 → 日和 · 映射”，左侧原始骨架与右侧人物共享时间轴；SDK与曲线采样差值约1e-6。近景放大只改变观察比例，不改变动作参数。默认从9.20秒明显动作前起播，可拖回0秒准备段。
- 对照截图中原始骨架双手举过头，而日和左右臂参数约+9.94/+9.96时仍为小幅张臂。当前这两个手臂通道不能呈现同等姿态，继续放大参数无法补出该动作。需要扩展绑定或选用具备抬臂/肘腿自由度的角色，才能追求更完整舞蹈。
- 当前没有将固定研究舞蹈接入音乐，也没有修改日常桌宠动作编排。研究源数据与生成的完整轨迹只在本机，未随app或源码包分发。
