# Stage35 真实音乐执行接入

## 本次做什么

把 DANCE-03（规划）+ Stage34（可靠性门控）接到**真实音乐**：研究窗口「音乐执行 · 集成」新增「真实音乐 · 系统声音」按钮——用 SOUND-01 的全系统采集抓当前系统播放的音频（网易云/任意应用），实时分析特征（BPM/能量/状态），离线分析 6.5 秒后生成初始舞句计划并执行；运行中每 10 秒用最近特征**增量重新规划**（`setPlan` 从当前音乐时间平移），使长歌持续贴合。门控在此模式下自动启用（可信→拍对齐，不可信→反应式降级）。

顺带修复两个此前阻塞真实音乐验证的问题：
1. `send()` 广播不含动作解剖窗口 → 研究页收不到 `music-signal`（已加白名单 + 窗口广播 + `musicAudioStart` IPC 白名单）；
2. 研究窗口后台节流导致 BVH 编译卡死（`backgroundThrottling:false`），真实模式循环改用 `setInterval` 避免遮挡暂停 rAF。

## 结果、验证与结论

**用本地生成的 70 秒合成音乐（120 BPM，经系统播放）验证完整链路**：

| 项 | 结果 |
| --- | --- |
| 系统采集 → 分析 | BPM **120** 正确、tracking 1.000、置信度 1.000 |
| 初始规划 | 成功（舞句计划生成，模式 quiet/rising 随能量变化） |
| 执行 | elapsed 持续增长，舞句按计划切换（第 2→3→4 句…） |
| 门控 | 「拍对齐（可靠）· tracking-locked」 |
| 增量规划 | **每 10 秒触发**（10.0s / 20.0s / 30.1s 三处日志确认），`setPlan` 平移生效 |

**结论**：真实音乐（系统声音）→ 特征 → 规划 → 执行 → 门控 → 增量重规划 的全链路在真实音频下跑通，不再受后台节流影响。**已知瑕疵**：扩展次数的 UI 计数未更新（功能已触发，仅显示计数问题）；真实歌曲下的观感需用户实际听歌确认。

**素材限制**：本机研究素材只有一段 61 秒 BVH 舞段，动作用于"重新组织"而非"多风格选择"。
