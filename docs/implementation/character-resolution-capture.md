# 角色清晰度与截图层级 · 2026-11-04

## 问题与目标

用户反馈千驮谷筱发虚，第三方截图工具有时被桌宠盖住；补充明确希望保留角色，以便截图角色本身。本轮目标是让角色按屏幕分辨率渲染，并使用合理的置顶层级，第三方截图时保持角色可见。

## 事实与修改

**清晰度事实：** 实际日常窗口的 `devicePixelRatio=2`，角色 CSS 区域 290×356，但 Canvas 仍为 290×356。Three.js 只在启动时收到一次像素比；后续屏幕缩放变化没有同步，导致低分辨率画布被放大。

新增 `src/rendering/pixel-ratio.mjs`，在布局变化和可见渲染帧同步当前像素比，仅比值变化时更新渲染器；桌宠最少 2×、最多 3×，CSS 尺寸与点击坐标不变。实际修复后为 580×712；开发仿真 3×→1×→2× 时分别得到 870×1068→580×712→580×712，最低 2× 为小窗口提供超采样。研究用途的同一 Character 使用原生比例，仍限制最高 3×。

**层级事实：** 原来角色、气泡和音乐面板使用 `screen-saver` 级置顶。按 [Electron 官方说明](https://www.electronjs.org/docs/latest/api/base-window#winsetalwaysontopflag-level-relativelevel)改为普通 `floating` 层，仍在普通应用窗口之上；实际 macOS 窗口元数据确认角色层级为 3。第三方截图不触发隐藏，也未设置截图排除/内容保护，角色仍可被截取。没有保留临时隐藏菜单或新快捷键。

**自带框选：** 原来用于交办屏幕上下文的入口已经会暂时隐藏角色。本轮补齐所有本应用窗口的统一挂起与恢复，并阻止框选期间激活、异步研究页加载等入口重新弹出窗口。结束后只恢复原来可见的窗口，使用无抢焦点恢复；用户关闭角色、窗口销毁、退出或锁屏时不强制重现。此行为只用于木漏日自身的框选入口，不关联 PixPin 等第三方工具。

## 验收与限制

- 260 项测试全部通过，Vite 构建及 macOS 临时签名打包通过。新增三项回归覆盖 DPR 动态更新、稳定帧不重复分配、采样上下限，以及所有窗口隐藏、嵌套持有、取消/失败恢复、原隐藏选择和窗口销毁。
- 本机实际运行测试包：角色区域 580×712、角色可见且无加载错误；实际窗口截图为 580×880，人工查看角色边缘和面部。图片只留本机，未加入源码。
- 实机确认窗口处于 macOS layer 3；未声称已覆盖每个第三方截图工具及其编辑模式。尝试系统截图快捷键未形成可核验的选区状态，因此不作为截图工具端验收证据；自带框选取消/恢复以确定性回归为准，未补充完整实机流程证据。
- 最低 2×、最高 3× 会增加低密度屏幕上的 GPU 像素工作量；本轮未修改模型、纹理、舞蹈编排、音乐信号或录制方式，也不代表长期多屏与所有截图工具体验已验收。

后续由用户在实际使用的第三方工具中确认选区和编辑面板的层级。若仍有遮挡，按具体截图工具的窗口层级定位，不默认用隐藏角色替代截图需求。
