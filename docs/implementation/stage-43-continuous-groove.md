# Stage43 连续律动引擎（无动作库的即兴反应）

## 本次做什么

用户指出："所有动作都是那么几个，无非在有限集合里排列组合，这不是我要的"——选择方向：**程序化连续律动（真正即兴反应，无动作库）**。

新增 `src/motion/continuous-groove.mjs`：
- 每帧由音乐信号**连续驱动**全身，无动作库、无主题/片段切换；
- 分层：基础层（能量→幅度）、节拍层（BPM 时钟驱动膝盖弹动/重心摇摆/踏步）、频谱层（低频→蹲/腿、高频→头/手臂）、事件层（onset 脉冲）、情绪层（能量曲线）；
- 全部通道低通滤波（smoothTo），保证动作有机连续；
- 关键修复：多拍周期（0.5/0.25 倍频）必须用**连续拍数**而非拍内相位，否则 sin 在拍回绕处跳变（测试发现 0.35 rad 跳变）；
- 桌宠侧：用 BPM 自建节拍时钟（music-signal 只有 onset 事件，无连续 beat 相位）+ 关节映射（VRM0 符号）。

## 结果、验证与结论

- 单元测试 5 项通过（连续、能量响应、无跳变、脉冲、静息）；
- 渲染验证（真实歌曲）：手臂摆动/抬举、腿弯、身体摇摆连续变化；
- 桌宠实测（dataset 检查）：grooveActive=true、energy 0.48-0.93 变化、beat 时钟推进 52.9、weight 0.9；连续帧截图显示姿态连续变化；
- 222 测试通过。

**技术判断（重要）**：
- 连续律动的表现力有上限——它能做到"听歌自然晃动/反应"，但**无法产出大幅编舞动作**（跳跃/旋转/踢腿等）——那需要动作数据（动捕或生成模型）。
- 生成模型（Bailando/EDGE）能产出大幅动作，但动作词汇来自训练数据集（AIST++ 编舞），本质仍是"数据集内组合"。
- 二者是不同取向：连续律动 = 无库但幅度小；生成模型 = 大幅但受数据集限制。

## 进一步评估与下一步

- 观感反馈：幅度是否足够、是否需要更多身体维度（跳跃/蹲起/甩头）。
- 若要大幅动作：可把生成模型动作与律动混合（模型提供大动作，律动提供连续背景）。
