# 起音传递与身体重音修复

日期：2026-11-03。用户指出《Boom Boom Pow》相比此前节奏感明显减弱。本轮针对音乐观测→宿主传递→身体回应接口，保留原有连续素材、手部平滑与裙摆约束。

## 事实与修复

音频 worker 原先只返回 PCM 批次最后一帧 features。该帧 lastOnsetFrame 可以指向刚检测到的起音，但 onsetStrength 是最后 10ms 窗口的瞬时低频通量，往往已归零。Character 看到新起音时读到零强度，播放器的 >0.12 门限于是取消回应。

24 秒原创 PCM、43 次已检测起音对照：20/40ms 批次原先各有 27 次被压制；80ms 有 38 次；120ms 有 40 次。新增宿主适配器按时间顺序保留 onset 事件原始强度到 lastOnsetStrength，再合并 features；四种批次均保留 43 次的起音强度，不引入未来事件，换流清空状态。不修改独立音乐信号库或 vendor DSP。

原先脉冲以固定绝对值减去 dt/0.12，小强度持续时间随之缩短，最低回应可能一帧就归零。现改为幅度无关的 100ms 指数衰减，保留短攻击；髋部下沉上限由 12mm 改为 28mm、躯干前倾上限 0.025→0.06rad。只叠加短促身体回应，手臂素材不变，不用逐帧音乐强度缩放骨骼。

Character 对新流重新消费起音，拒绝年龄超过 180ms 的旧事件。幅度仅由已检测的起音强度决定，不把起音伪装成可信 BPM 或小节。材料相位估计和音乐可靠性门控仍保留。

## 验证与限制

合成回归覆盖 PCM 批次、跨批次强度保留、未来事件隔离、流重置，以及 30/60/120Hz 下弱起音在 100ms 后仍有身体回应且手臂轨迹不变。全套本机 241 项测试和构建通过。

真实歌曲链路：本机网易云《Boom Boom Pow》从原暂停位置实播 20 秒（未重新选曲或回到开头）；结束时发送暂停命令，稍后复核仍为 playing，恢复暂停未确认。50ms 轮询共观察 47 次新起音，原先瞬时强度门限会压制其中 34 次；新增字段保留 47 次强度，实机身体脉冲峰值 0.636，无运行异常。模式为 onset-reactive/tempo-only，未观察到稳定材料相位锁定。这是传递与响应验收，不是 47 个真实音乐拍点的人工标注。

这证明已检测起音不再因传递和包络而消失，不证明真实歌曲所有鼓点均被检测到，也不代表舞蹈重音已准确踩拍。真实歌曲链路与用户观感分别记录，M1/M2 不因此完成。
