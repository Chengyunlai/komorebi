# 烟花与录像连续性优化

日期：2026-11-03。用户要求先优化观感，再重新录制同一首歌40秒。目标为消除已确认的录像停顿，让音乐重音与明确手势共同决定烟花触发；不改人物素材或切歌取消逻辑。

## 已确认归因

使用已录 Boom Boom Pow PCM，经现有 MusicAnalyzer/music-signal-delivery 离线生成观测，临时注入实际 Character 与 MusicFireworks props，测试后恢复原值。不替换音乐DSP或添加假拍点。

同输入21秒对照，烟花开/关均采到1262个rAF，均无>90ms间隙或longtask。烟花开启时，Page.startScreencast 有6段约267–283ms捕获间隙；关闭时无此间隙。个别间隙对应第二Canvas动画开始/结束附近。证据支持“本机这一捕获路径受额外动画Canvas影响”，不将其泛化成所有Chromium环境的上游缺陷。

独立 Page.captureScreenshot 能绕开周期性间隙，但实际吞吐约15fps，未采用作交付。改用 macOS screencapture 指定桌宠 windowId：隔离回放约22秒/1270帧，最大PTS间隔50ms，rAF仍连续。原先暂停后跳姿态属于成片捕获缺口，保持原身体执行和切歌修复。

## 视觉调整

`selectFireworkHand` 现在必须满足明确抬手或向外伸展门槛：抬高手高于胸部约0.10个视口短边，或水平伸展>0.16且手不低于胸部约0.06短边。保留面部/离屏/过期拒绝。没有合适手势就跳过音乐起音，不再强选两只低垂手中较好的一只。

烟花生命周期1.65→1.15秒；24–32条径向亮尾，短促中心星芒，取消独立的完整圆环轮廓。半径最多46 CSS像素，较清楚地从手边爆开。每色缓存柔光粒子贴图，代替逐颗粒逐帧shadowBlur；未新增素材或依赖。仍至少2.2秒间隔、同屏最多一朵，音乐只依据已观测起音/能量对比，不声称识别高潮。
