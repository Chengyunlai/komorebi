# 日常舞蹈播放连续性修复

后续反馈：用户仍指出手裙穿入与慢感；默认平滑和交叠配置已由 [手裙与节奏修复](garment-clearance-rhythm.md) 更新。下文保留本轮当时配置和证据。

日期：2026-11-03。任务：人物有抖动感，尤其是站在原地时手部来回碎抖。目标是保留完整身体动作、改善连续性；不以过滤器输出或帧率单项代替整段观感验收。

## 事实与归因

- 旧动作库 IPC 将 23 支舞共 15,364 帧直接合并，没有返回实际素材边界。播放器可能把两支舞的尾/头作为相邻帧插值，且跨段跳变会污染活动度基准。
- 旧选段只看单帧平均角速度。手部活动也能满足阈值，没有验证后续整段的腿部/身体参与度；起音可在段长 60% 时提前切段。
- 旧过渡的离段侧固定为切换时的静态姿态，入段侧继续前进。源音乐的原始能量/重音还会逐帧缩放相对 rest 的骨骼角度，静止素材也会因此抖动；脚目标却没有同步改变。
- 可见窗口旧逻辑以 `now-lastRender<1000/30` 丢帧，实测约 22.95 FPS。
- Bailando 会在音乐播放后自动启动，且片段给桌宠重复发送；流式骨骼写入后，动作库末端执行仍会覆盖身体。此为来源竞争问题，不能由滤波参数解决。

这些事实对应三块知识接口：音乐观测应控制可解释的时间/活动度目标；舞蹈材料必须保留时间边界与身体参与信息；身体执行只能有一个完整姿态目标。足部 IK 无法修复上游时间切片、手部独动或多来源覆盖。

## 修复

1. `electron/dance-library.cjs` 根据实际加载帧数返回每支舞包含端点的 `start/end`，跳过缺失素材，不信任旧 manifest 的帧数。
2. `createFreestyleMotionPlayer` 以连续窗口平均活动度、身体参与度与开头参与度选段；使用窗口活动度的分位数基准，不以跨素材跳变的最大值归一化。姿态匹配后，再对少量候选比较有向角速度。
3. 日常段长由 2.4s 改为 4.8s；起音不再提前打断。过渡两侧继续播放，采用五次平滑权重，预留离段侧尾部材料；插值不越过各自源舞段。
4. 移除音乐逐帧角度缩放。能量控制选窗，BPM 经 0.5s 时间常数平滑后控制速度；旋转、髋位移、双踝目标共同使用 0.06s 时间常数过滤，避免身体与脚目标各走一条时序。该过滤约带来几十毫秒滞后，不能恢复素材缺失的信息。
5. 启停淡入/淡出。可见窗口逐 rAF 更新，隐藏时仍降频。动作库无需旧 BVH 研究参考即可独立载入。
6. 日常不再自动启动研究生成器；显式启动流式实验时与动作库互斥，停止时清理队列；修正重复广播、未声明的过渡状态及队列裁剪。退出时关闭生成子进程。

## 验证与范围

合成回归覆盖：静止源不被快速能量/重音抖动；有协调身体材料时排除手部独动窗口；起音不打断完整窗口；移动离段保留速度；素材边界；停止淡出；缺失文件与错误 manifest 帧数不破坏边界。先运行 [example](../../examples/motion-continuity/README.md)，再读 core。

同一份本机 23 支动作库、同一段 60 秒合成控制输入，在相同 2.4s 段长、0.6s 过渡、60Hz 采样下比较控制器（不是实机骨架测量）：

| 指标 | 旧版 | 修复候选 |
| --- | ---: | ---: |
| 手臂速度变化 P95（相邻帧速度模长差 / dt，rad/s²） | 323.81 | 38.40 |
| 单手臂关节速度峰值（rad/s） | 26.33 | 12.44 |
| 60 秒切段次数 | 39 | 24 |
| 单次 step 耗时峰值（本机，ms） | 7.12 | 5.25 |

速度变化 P95 降低约 88%。这是该固定输入上的代理指标，不等于加加速度，也不等于所有动作均已自然。日常最终配置为 4.8s，以上保留相同段长便于比较。

本机 `npm test`：228/228 通过；`npm run build` 通过。

当前本机实际桌宠：完整载入 23 支/15,364 帧；来源为 `library`，音频在本机分析，生成器 `off`；WebGL 绘制采样 4 秒内约 59.74 FPS，旧版约 22.95 FPS；监测未发现运行异常。本机录像与数值摘要留在 `docs/evidence/`，不随源码发布。

## 待验收与限制

本轮解决播放控制和来源竞争，不修改音乐分析算法，也未重训/重新制作角色或动作。0.06s 过滤存在滞后，源重定向和足部约束仍可能改写动作；素材只有手部运动时，播放器不能凭空生成舞步。流式生成仍是研究路线，不把它的单独观感计为日常路线通过。

需用户继续观察完整舞段、安静音乐、暂停/恢复与跨段处的手部细节，按 M1/M2/M3 验收；不得将本轮数值和 FPS 改善直接标为里程碑完成。
