# Stage21 完整窗口脚部归因

## 1 本轮做什么

对选中48秒候选的完整4秒源/目标窗口，记录踝部路径、速度、朝向和脚位移差。源路径按既有身体适配的水平朝向与腿长尺度转换，只比较各脚相对窗口起点的增量；不能把归一化骨踝高度当脚底/地面误差。

脚部证据在过渡中必须来自两侧，混合期间一律保持unknown，避免沿用旧出段plant。人工标注plant与运动学估计plant分别汇总，未知不生成锁脚。研究页执行完整窗口评估并恢复原显示姿态；example `examples/stage-21-foot-window/user_code/main.mjs`。断点：源/目标坐标变换、相对位移差、证据knowledge、分段锚点、缺帧处理。

## 2 结果与验证

按实际实现、测试和原生VRM结果补充。

## 3 资源和调整

无需新增模型；当前缺少模型脚底偏移和可信接触标注。以踝部/脚骨为观测点，不自动宣布物理接触、穿地或承重。

## 4 进一步评估

区分源运动/源混合已有的脚位移和身体适配额外引入的位移，再选择接触计划/身体适配修正。不能简单把所有脚固定；滑步、提脚与转身仍需保留。

### 已执行验证与结论

- `npm test`143/143通过，覆盖坐标/尺度对照、相反方向旋转、完整旋转基变换、缺帧和原子校验、估计/标注窗口分开、混合期未知接触及非二进制小数过渡端点（0.8-0.5会稍大于0.3，采样边界已修正）。构建通过。
- 合成身体91采样，脚的对齐位移差约1e-16m，证明在已知一致运动中不会凭空产生位移误差。旋转比较使用适配器完整基变换C；位置/根运动保持水平yaw+腿长尺度，两者不混用。
- 原生VRM检索48秒review候选，0–4秒/60Hz共241样本、0gap。两次聚合JSON完全一致；前后elapsed=1.200、源起点9/48、planar/fixed18不变，canvas截图SHA256完全一致，renderer/UI errors为空。没有原始姿态导出。
- 完整窗口左/右踝相对起点的对齐增量差最大0.205557/0.310462m。源脚原米路径3.42713/3.96086m，目标4.10906/4.64265m，尺度约1.13448，不能将未缩放路径直接相减。
- 左脚outgoing的估计plant窗口0–0.8167秒：源漂移0.007333m，目标0.109113m。右脚outgoing的0.9333–1.4833秒：源0.005116m，目标0.185517m。源换到目标尺度仍远小于目标踝漂移。没有annotatedPlant窗口，混合期保持unknown。

结论：在源脚接近静止的区间，身体映射仍引入显著踝部位移；旋转增量保真不足以保证端点轨迹保真。这是身体执行层的可归因缺口，不能全部归于音乐或动作选择。当前观测是normalized VRM脚骨，不是网格脚底；没有脚底偏移和测量地面，所以不将差值称为物理滑脚/穿地误差。

下一轮实现源踝轨迹的目标身体适配和可达性检查，保留抬脚、滑步和转身的源运动，不用未知接触强制plant；同时记录腿部旋转改写和目标端点误差。先对该窗口做关闭/开启的真实角色对照，再决定是否进入日常音乐执行链。
