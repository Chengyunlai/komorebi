# 声音敏感陪伴者（Sound-Reactive Companion）设计

更新：2026-10-29。状态：**产品定位已确认，尚未进入实现**。与[音乐舞蹈黑板](music-dance-blackboard.md)并行，不取代舞蹈主线（M1/M2 验收保留）。

## 产品定位

木漏日从「音乐舞蹈原型」扩展为**对声音敏感并做出反馈的陪伴者**：它持续聆听电脑内部声音（音乐、通知、视频）、外部麦克风（人声、房间声音）与输入事件（键盘/鼠标），把听到的变成可解释、有喜剧感的角色反应。**舞蹈是其中一条响应路线**，不是唯一目标；口型、节拍律动、事件反应、情绪能量是并列的响应类别。

与现有主线并行推进：舞蹈主线（DANCE-01 等，P0）保持原验收目标；声音响应作为独立能力线（P1）推进，最终并入 M3 日常桌宠验收。

## 声音源与现状

| 声音源 | 现状（代码事实） | 差距 | 验收维度 |
| --- | --- | --- | --- |
| 电脑内部系统输出（音乐/通知/视频） | `electron/native/audio-tap.swift` 只 tap 网易云进程（`monoMixdownOfProcesses` 过滤 netease bundle id），经 `music-audio-worker.mjs` 进入 MusicAnalyzer | 改为全系统输出采集；保留网易云入口不变 | 任意应用出声均产生特征流；通知/视频/音乐事件可分类；网易云入口回归不变 |
| 外部麦克风（人声/房间声音） | 无采集链路 | 新增麦克风采集（AVAudioEngine/CoreAudio 输入）与系统权限 | 房间声音进入同一特征流；与系统输出可叠加或分离 |
| 键盘/鼠标输入事件 | 无 | 新增输入事件观测（非声音源，事件驱动） | 按键/点击触发轻响应，不占用音频链路 |

## 响应类型学（callback 分类）

从「听到什么 → 做什么」组织，不把所有响应都当跳舞：

| 类别 | 触发 | 现有可复用 | 新工作 |
| --- | --- | --- | --- |
| 节拍/起音同步（点头、晃肩、打响指） | onset / beat 特征 | MusicAnalyzer、musical-director、music-motion-simulator | 映射到新角色的待机级动作 |
| 口型跟随（人声/唱歌） | 语音能量 | wlipsync + MiMo（已就绪） | 无 |
| 事件反应（通知声→抬头侧耳、暂停/静音→收势待机） | 全系统输出的事件特征 | 现「静音收势」逻辑 | 事件分类（通知 vs 音乐）与对应反应 |
| 情绪能量（激昂→夸张动作/表情） | 能量包络 | music-motion-simulator 轻重响应 | 新角色夸张表达 |
| 输入事件响应（打字/点击→轻微点头） | 输入事件 | 无 | 新观测链路 + 轻动作 |

## 人物呈现方向

- **渲染路线**：3D 卡通 VRM + toon/描边着色。复用整套动作/舞蹈管线（重定向、IK、动作库、接触）不变，只换模型资产与渲染样式。
- **角色形象**：原创喜剧卡通真人——「茶杯头式橡皮管美学（1930s 手绘卡通气质）+ 夸张喜剧反应」（用户所提「邓超类型」指夸张、会演、反应浮夸的原创真人风角色，非真实名人肖像）。不复制茶杯头具体角色资产，不使用真实人物肖像。
- **橡皮管「拉伸/变形」**：VRM 骨骼为刚体旋转，用骨骼缩放/层级变形模拟，属于待验证设计（见 H-风格1）。
- **toon/描边**：扁平着色 + 轮廓线（后处理或双面膨胀），实现细节待验证。
- **资产边界**：新角色资产自制或获授权后使用；未获授权不随包分发（延续 RELEASE-01）。现有 Jessair 等 VRM 与日和 Live2D 研究窗口保留。

## 与三块黑板的接口

- 复用 [音乐舞蹈黑板](music-dance-blackboard.md) 的 MusicObservation（时间/能量/起音/节拍及不确定性）——MusicAnalyzer 与声音来源无关，系统输出与麦克风共用同一特征管线。
- 新增观测对象：`InputEventObservation`（键盘/鼠标事件，非声音）；`SoundSource`（系统输出/麦克风）标识，用于叠加与分离。
- 响应执行仍走「表达状态 → 动作/参数」：舞蹈是表达状态的一种，待机、口型、事件反应、节拍律动是其他种。音乐信号与人物动作决策分开维护的约定不变。

## 事实 / 假设 / 验收

**事实（代码已确认）**：MusicAnalyzer 是来源无关的通用 PCM 分析；现有 tap 仅针对网易云进程；Live2D 曲线→参数映射已在研究窗口证明；wlipsync/MiMo 口型已就绪。

**假设**：
- H-声音1：macOS 14.2+ 可实现全系统输出 tap（现有代码已验证进程级 tap，输出级的具体 API 方式待验证）。→ **已实测确认**（Stage27，macOS 26.3）：`CATapDescription(monoGlobalTapButExcludeProcesses:)` 经 `AudioHardwareCreateProcessTap` 创建成功，任意应用出声产生特征流。
- H-声音2：通知声、视频声、音乐可在特征层区分（不保证全部正确，先以分类准确率验收）。
- H-风格1：橡皮管拉伸/变形可用骨骼缩放近似到可接受观感。

**验收**：每个声音源有可执行断言（特征流到达、事件分类准确率、权限失败路径）；观感验收以「声音变化带来可解释反应」为准；声音线不替代舞蹈 M1/M2 验收，也不把局部指标当观感证据。
